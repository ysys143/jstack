# Host rules

The documented behavior the host setup audit applies when it projects a listing, orders precedence, or names a collision. [host-rules.json](host-rules.json) is the source of truth; this page is a readable copy. Every rule names an official page, and a `quote` that must still appear on that page. Seven rules are not documented anywhere and are marked `observed`.

Verified 2026-10-06 against Claude Code 2.1.291 and Codex CLI 0.160.1; the listing eligibility, host-skills and synced-override-key rules were measured on Claude Code 2.1.292 on 2026-10-07. Values that name a unit are the numbers the audit computes with; the others state a behavior.

## Claude Code

| Rule | Statement | Value | Source |
| --- | --- | --- | --- |
| `claude.skills.locations` | Claude Code loads skills from the enterprise managed settings directory, \~/.claude/skills, the project .claude/skills (from the start directory up to the repository root, plus nested directories), directories passed with --add-dir, enabled plugins, and the claude.ai account. A Markdown file in .claude/commands/ is the older format and still works. |  | <https://code.claude.com/docs/en/skills> |
| `claude.skills.precedence` | For a skill name defined in more than one of enterprise, personal and project, enterprise wins over personal and personal wins over project. A skill wins over a same-name file in .claude/commands/. | `enterprise>personal>project` | <https://code.claude.com/docs/en/skills> |
| `claude.skills.plugin-namespace` | A plugin skill is namespaced as /plugin-name:skill-name, so it loads alongside a same-name skill at any other location instead of replacing or being replaced by it. |  | <https://code.claude.com/docs/en/skills> |
| `claude.listing.desc-cap` | The combined description and when_to_use text of a skill is truncated at 1,536 characters in the skill listing. The skillListingMaxDescChars setting changes the cap. | 1536 characters | <https://code.claude.com/docs/en/skills> |
| `claude.listing.budget-fraction` | The skill listing is capped at a share of the model's context window, 1% by default. The skillListingBudgetFraction setting changes the share. | 0.01 fraction | <https://code.claude.com/docs/en/settings-reference> |
| `claude.listing.fallback-chars` | When the context window is not known the listing budget falls back to 8,000 characters. SLASH_COMMAND_TOOL_CHAR_BUDGET replaces the computed budget with a fixed character count. | 8000 characters | <https://code.claude.com/docs/en/env-vars> |
| `claude.listing.drop-order` | When the listing overflows its budget, Claude Code keeps every skill name and drops descriptions starting with the least-invoked skills, so the most-used skills keep their full text. |  | <https://code.claude.com/docs/en/skills> |
| `claude.listing.overrides-not-plugins` | The skillOverrides setting does not apply to plugin skills. Plugin skills are managed through /plugin. |  | <https://code.claude.com/docs/en/settings-reference> |
| `claude.listing.synced-override-key` | A skill synced from claude.ai is listed as `anthropic-skills:<name>`, and a skillOverrides entry under that full name always applies to it; when both keys are set the full name wins. An entry under the bare name applies to it only while no other loaded command holds that name. A user or project skill holds its folder name and its frontmatter name, and takes the entry for itself only under its folder name. A user or project command holds the name it is listed under (its file name, or ns:name in a subfolder, which no bare name equals) and not its frontmatter name. A plugin skill or command holds a name only when its frontmatter gives that name without a colon; its folder or file name alone does not hold, and overrides never apply to it. Names are compared without regard to case. |  | observed (see below) |
| `claude.listing.eligibility` | A skill or command is listed to the model unless disable-model-invocation is set or skillOverrides turns it off or to user-invocable-only. A plugin skill or command is listed only when its frontmatter gives a description or a when_to_use; one with neither costs nothing in the listing, can still be typed, and is not blocked from model invocation. |  | observed (see below) |
| `claude.listing.host-skills` | Claude Code puts its own skills and prompt commands in the same listing and under the same budget. They are not files in the profile, so the audit counts them as an observed figure and treats them as kept first: when the listing is over budget, bundled entries keep their full text and the other entries share what is left. | 6600 characters | observed (see below) |
| `claude.listing.chars-per-token` | The listing budget in characters is the context window in tokens x characters per token x the budget fraction, rounded down. Characters per token depend on the model: 4 for the claude-3 family, opus 4-0, 4-1, 4-5 and 4-6, sonnet 4-0, 4-5 and 4-6 and haiku 4-5, and 3 for every other model, so current models get 3. With no known window the computation uses 200000 tokens, which gives the documented 8,000 characters only at 4 characters per token. | 3 characters | observed (see below) |
| `claude.listing.entry-format` | A listed skill or command is the line `- name: text` and costs the name plus 4 characters plus the text; an entry shown without a description is `- name` and costs the name plus 2. The text is the description, followed by ` - ` and when_to_use when there is one, cut to the per-skill cap. The lines are joined with newlines, one character for each entry but the first, and the host counts each line in display width, so a CJK character counts 2. The listing is over budget when this sum exceeds the budget. |  | observed (see below) |
| `claude.listing.usage-score` | When the listing exceeds its budget every entry first costs its name-only line, and the rest of the budget goes to descriptions in order of usageCount x max(0.5^(daysSinceUse/7), 0.1), highest first, ties in listing order. An entry whose description does not fit stays name-only and the next entries are still tried, so a smaller description can fit after a larger one was skipped. A skill with no recorded use scores 0. Usage is looked up under the command's own name: the qualified name for a plugin skill (jstack:plan), the short name for a skill synced from claude.ai (pdf). |  | observed (see below) |
| `claude.agents.precedence` | For subagents sharing a name Claude Code uses the highest-priority location: managed settings, then the --agents flag, then .claude/agents/, then \~/.claude/agents/, then a plugin's agents/ directory. | `managed>--agents>project>user>plugin` | <https://code.claude.com/docs/en/sub-agents> |
| `claude.agents.description-warning` | When the combined descriptions of the subagents, built-in ones excluded, pass 15,000 tokens, Claude Code shows a warning at startup and still loads every subagent. | 15000 tokens | <https://code.claude.com/docs/en/sub-agents> |
| `claude.mcp.scopes` | A server defined in more than one place connects once, using the whole entry from the highest-precedence source: local, then project, then user, then plugin-provided servers, then claude.ai connectors. Duplicates across the local, project and user scopes are matched by name; plugin servers and connectors are matched by endpoint, so one that points at the same URL or command as an enabled server above is a duplicate. Fields are not merged across scopes. | `local>project>user>plugin>connector` | <https://code.claude.com/docs/en/mcp> |
| `claude.mcp.tool-search` | Tool search is on by default, so only MCP tool names and server instructions load at session start and tool definitions are deferred until Claude needs them. |  | <https://code.claude.com/docs/en/mcp> |
| `claude.mcp.description-cap` | Claude Code truncates each MCP tool description and each server's instructions at 2,048 characters by default. CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH changes the limit. | 2048 characters | <https://code.claude.com/docs/en/mcp> |
| `claude.hooks.plugin-merge` | When a plugin is enabled its hooks merge with the user and project hooks. The same handler in several settings files runs once, but a plugin's copy of the same handler stays separate and runs in addition. |  | <https://code.claude.com/docs/en/hooks> |
| `claude.diagnostics.plugin-details` | claude plugin details reports a loaded plugin's component inventory and its projected token cost, the always-on tokens the plugin adds to every session. |  | <https://code.claude.com/docs/en/plugins/cli-reference> |

## Observed rules

These are read from a host binary, not from documentation, so they carry `evidence` instead of a page. `claude.listing.chars-per-token` and `claude.listing.usage-score` were first recorded in `docs/skill-routing-principles-20260915.md` (section 5, observed in 2.1.272); Claude Code 2.1.291 differs from that record in two places, the characters per token and the keep order.

- `claude.listing.chars-per-token`: the listing budget in characters is `floor(context window x characters per token x skillListingBudgetFraction)`, with 4 characters per token for the claude-3 family, opus 4-0, 4-1, 4-5 and 4-6, sonnet 4-0, 4-5 and 4-6 and haiku 4-5, and 3 for every other model. Search `return JI.has(r)?4:3}` in `~/.local/share/claude/versions/<version>`; the set `JI` is declared just before it, and the budget function sits next to the constants `=0.01,k=4,m=200000`.
- `claude.listing.entry-format`: a full entry is `- name: text` (name + 4 + text), a name-only entry `- name` (name + 2), lines joined by newlines, and the text is `description - when_to_use` cut to the cap. Search `Skill listing over budget: ${` and read the function around it.
- `claude.listing.eligibility`: the predicate that selects model-listed commands ends with `e.loadedFrom==="commands_DEPRECATED"||e.hasUserSpecifiedDescription||!!e.whenToUse`; search that literal in `~/.local/share/claude/versions/<version>`. A plugin entry satisfies it only through a description or a `when_to_use`.
- `claude.listing.synced-override-key`: search `answer only to anthropic-skills:<name>` with `grep -a -c -F` in `~/.local/share/claude/versions/<version>` (on 2.1.292 the lookup itself reads `bareNameReserved?void 0:`), then set a bare key and the full-name key in settings and read the attachment of type `skill_listing` in a new session transcript under `~/.claude/projects`. On 2.1.292 a bare key reached the synced skill only while no other loaded command held the name: a user or project skill held its folder name and its frontmatter name (a key reaches it under the folder name only), a top-level user or project command its file name but not its frontmatter name, a plugin skill or command only a frontmatter name without a colon and never its folder or file name; a command in a subfolder (`ns:pptx`) and an agent did not hold it, names were compared without regard to case while a key was matched by its exact spelling, and the full-name key always applied. The same binary reading puts the commands and bundled skills of Claude Code itself in the reserved set; that was not probed.
- `claude.listing.host-skills`: in a session transcript under `~/.claude/projects`, read the attachment of type `skill_listing` and sum the lines whose name has no plugin prefix and is not one of your own skills (5,690 and 6,622 characters in two sessions on 2.1.292); the literal `source==="bundled"` marks the entries the reduction keeps in full.
- `claude.listing.usage-score`: when the listing is over budget, descriptions go to entries in order of `usageCount x max(0.5^(daysSinceUse/7), 0.1)`, highest first, ties in listing order; an entry that does not fit stays name-only and the next ones are still tried. Search `.usageCount*Math.max(` for the score and read the loop after `Skill listing over budget: ${` for the order.
- `codex.listing.path-alias`: Codex prints a skill's path as a root alias plus the path under that root, `(file: r11/workflow/plan/SKILL.md)`, with the aliases defined in a `### Skill roots` block of the same listing. The Codex 0.160.1 binary contains the text ``expand the matching root alias first from `### Skill roots` ``, and Codex session logs under `~/.codex/sessions` hold the rendered listing. Search that literal with `grep -a -o -F` in the native binary under the npm package (`node_modules/@openai/codex-<platform>/vendor/<triple>/bin/codex`; resolve symlinks from the `codex` command), and `(file: r` followed by digits and a slash in a recent `rollout-*.jsonl`. The `### Skill roots` block itself is not counted.

The Claude binary is minified, so search these stable literals and never the helper names. A literal that is gone, or whose neighbors changed, means the behavior may have changed: read the code around it before keeping the rule.

## Refreshing the rules

Refresh when the install-time check reports `drift` for a page, or when an installed host is newer than the `hostVersion` its rules were verified on (`newerHosts` in `scripts/rules.ts` reports it).

1. Fetch each affected source through Jina Reader: `curl -s https://r.jina.ai/<source URL>`. The check reads the same rendering, so no other renderer is a substitute. For a new host version, refresh every source of that host.
2. Read what the page now says about each rule. Update `statement`, `value`, `unit`, `quote`, `verifiedAt` (today) and `hostVersion` (the installed version the rule was checked against). A `quote` stays one sentence or clause, copied verbatim, preferably plain prose. The check compares after normalization (emphasis and code marks removed, curly quotes straightened, whitespace collapsed), so a quote may keep the code marks the page shows.
3. When the page no longer says what the rule says, correct or remove the rule and the audit code that uses it. Never loosen a quote just to clear a drift. A new or removed rule also changes `RULE_IDS` in `scripts/types.ts`.
4. For `observed` rules, search the literals above in the new host binary (or, for the Codex path alias, in the new binary and a fresh session log) and update `evidence` and `hostVersion`.
5. Update the top-level `verifiedAt` and this page, then run `npm run build` and `node --test dist/skills/support/host-audit/tests/rules.test.js`.
