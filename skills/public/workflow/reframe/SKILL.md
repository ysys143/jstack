# Reframe — name it so it can be asked for

**A request that cannot name its problem cannot be delegated well.** The agent
guesses at the shape of the problem, and the guess decides what gets built.
The words exist already — usually in a field that solved the same problem
years ago under a different name.

Teach the user the expert words for what they are building. Start from their
own files, code, and description — not a summary of them. The gap between
their summary and their code is often the unnamed thing.

## Which problem is it

When their description could name more than one problem, list the two or
three problems it could be first. For each, give the one term that names it
and the sign that would tell it apart from the others. Then teach the words
for the most likely one and say why you picked it. Skipping this step teaches
precise words for the wrong problem.

## The four moves

1. **Teach 8 to 12 terms**, ranked by how much each would change what gets
   built. For each term give:
   - the word and its meaning in one plain sentence;
   - the part of their description it names;
   - one real project, paper, or system that uses it that way, with a link;
   - what it lets them ask an agent for.
2. **Borrow from 2 or 3 neighboring fields** that solved the same shape of
   problem under other names. For each field say what carries over, where
   the analogy breaks, and which terms come back. An analogy without its
   breaking point is decoration.
3. **Name what they did not mention** but should care about — the thing the
   vocabulary makes visible that the first description could not.
4. **Rewrite their description** with the new words. The rewrite is the
   deliverable they carry to the next step.

## Citations are checked, not suggested

Open every link and confirm it uses the term that way. Cut any citation you
cannot confirm — an unchecked link is a claim made on your authority. No
padding: drop a term rather than stretch a citation to keep it.

## Limits (stated)

This skill supplies vocabulary and a rewritten request. The judgment of
which problem is really theirs stays with the user — the disambiguation list
exists so they can reject the likeliest reading, not to decide it for them.
