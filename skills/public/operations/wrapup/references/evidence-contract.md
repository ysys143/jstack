# Evidence contract

공용 보고서 코어는 기록을 보고서로 바꾸는 과정에서 관찰·해석·확인 필요를
섞지 않는다. `wrapup`은 이 계약을 사용하는 사용자용 기간 보고서 진입점이며,
이 구분은 목적지와 무관하게 적용한다.

## Record shape

각 원장 항목은 다음 의미를 가진다.

| 필드 | 규칙 |
|---|---|
| `id` | 수집기와 원본 식별자를 합친 안정적인 단기 ID |
| `kind` | `git`, `filesystem`, `session` 중 하나 |
| `source` | 원본 시스템의 이름. 협업 공간 이름이 아님 |
| `observedAt` | 원본에서 관찰한 시각. 없으면 생략 |
| `project`·`path` | 원본 루트 기준 상대 위치 |
| `summary` | 원문을 과장하지 않는 짧은 설명 |
| `status` | `observed` 또는 `needs-confirmation` |

수집기가 실패하면 항목을 0으로 채우지 말고 경고를 남긴다. 수집기 자체가
설치되지 않았거나 인덱스가 갱신되지 않은 경우도 같은 규칙을 따른다.

## Promotion rules

- Git 제목은 작성자의 당시 의도다. 완료·승인·배포로 쓰려면 사용자의 확인이
  필요하다.
- 파일 생성·수정 시각은 작업 흔적일 뿐이다. clone, 빌드, 자동 생성물과
  사람이 한 작업을 구분하지 못하면 확인 필요로 둔다.
- 세션 제목·요약은 과거 대화가 있었다는 증거다. 현재 상태나 결론으로
  승격하지 않는다.
- 두 소스가 같은 작업을 가리키면 기록을 합치되, 더 강한 주장으로 합치지
  않는다.

## Empty and incomplete results

`records: 0`은 “업무가 없었다”가 아니다. 소스가 실제로 읽혔는지, 지정 범위가
맞는지, 세션 인덱스가 최근에 갱신됐는지를 함께 보고한다. 부분 실패는 성공
수치에 포함하지 않고 경고로 표시한다.
