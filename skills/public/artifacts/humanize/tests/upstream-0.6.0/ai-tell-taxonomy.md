# AI 한글 티 분류 체계 v3.1 (Korean AI-Tell Taxonomy)

> v3.1 변경: snflkd/fluent-korean(output-style, MIT) 예방 규칙 3종 선별 이식 — A-20('의' 연쇄·과밀), F-6(은유 어휘 오용), F-7(현학적 고어·희귀어). 모두 HOLISTIC·S3(코퍼스 미검증 자연스러움 규칙)로 편입. 추가로 E-2에 명사형 종결 조건부 구분(변주 유지 vs 전보체 제거) 명시. 또한 benelog "클로드 문체 없애기 지침" gist의 줄표(—) 규칙을 J-3에 흡수 — 용법별 치환(삽입구→괄호, 문장연결→분리, 제목부제→본문화)·코드/인용 예외·**콜론 치환 금지** 방침 명시.

LLM(ChatGPT·Claude·Gemini 등)이 생성한 한글 글에서 반복적으로 관찰되는 "AI 티" 패턴을 11개 대분류 × 서브 패턴으로 정리한다. 탐지기·윤문가·리뷰어가 공유하는 단일 진실 원천(SSOT). 각 패턴마다 (1) 정의, (2) 시그니처 예문, (3) 심각도(S1 결정적 / S2 강함 / S3 약함), (4) 윤문 처방을 제공한다.

## 규칙 클래스와 런타임 보증 (v2.0)

각 서브 규칙은 `- class:` 필드로 보증 등급이 나뉜다. `scripts/prescan.py`·`reconcile.py`가 이 필드를 파싱한다.

- **ANCHORED** — 특정 표층형(단어/구)이 방아쇠. `- 표층형:` 정규식을 함께 둔다. prescan이 입력을 결정적으로 스캔해 **모든 출현을 후보로** 뽑고, reconcile이 detector가 그 후보를 전부 flag/keep으로 소진했는지 **코드로 강제**한다. LLM 주의력과 무관하게 커버리지 보증.
- **COMPUTED** — 결정적으로 계산 가능한 문서 지표. `- 지표: <name> <op> <number>` 식을 둔다(`and`로 복합 가능). 사용 가능 지표: `sentence_len_stdev`, `em_dash_count`, `bullet_ratio`, `sentence_count`, `sentence_len_mean`, `char_count` + im-not-ai vendored `comma_inclusion_rate`, `ending_comma_rate`, `comma_segment_length`, `safe_balance_count`, `antithesis_count`, `double_particle_count`, `relative_clause_nesting`. 트리거 시 대응 finding이 없으면 reconcile FAIL.
- **HOLISTIC** — 순수 LLM 판단이 불가피한 잔여(맥락 의존). `- class:` 미표기 규칙은 HOLISTIC으로 간주(하위 호환). 소프트 보증임을 명시하고 최소화한다.

> 표층형/class 필드는 append-only로 점진 확대한다. 미주석 규칙도 detector는 종전대로 산문으로 판단하므로 시스템은 graceful하게 degrade한다. 새 패턴 승격 시 `korean-ai-tell-taxonomist`가 이 필드를 함께 채운다.

## 심각도 기준

- **S1 결정적(critical)**: 한 번만 나와도 "이건 AI"라고 거의 확신하게 되는 패턴. 무조건 제거.
- **S2 강함(high)**: 1~2회는 자연스러울 수 있으나 문서에서 3회 이상 반복되면 티 남. 밀도 기반 제거.
- **S3 약함(low)**: 개별로는 문제 아님. 다른 패턴과 중첩될 때 AI 인상을 강화. 리듬 조정 수준.

## A. 번역투 (Translation-ese) — S1~S2

영어·일본어식 구문을 한국어 어순·조사 체계로 무리하게 옮긴 흔적. AI 글의 가장 결정적 시그니처.

### A-1. "~에 대하여/대해서" 남발 [S1]
- 패턴: `X에 대해(서) Y` (영어 `about/regarding X`)
- 예: "AI 규제**에 대해** 논의할 필요가 있다" → "AI 규제를 논의해야 한다"
- 처방: 목적격 조사로 직결. 또는 주제 조사 "는".

### A-2. "~를 통하여/통해" 남발 [S2]
- 패턴: 수단·경로를 거의 모두 "통해"로 처리 (영어 `through/via`)
- 예: "데이터 분석**을 통해** 인사이트를 얻는다" → "데이터를 분석해 인사이트를 얻는다"
- 처방: **한 문서에서 반복 재사용될 때만**(문단 3회+) "~로", "~해서", "~함으로써"로 분산. 1~2회는 보존.
- 심각도 이력: v3.0(상류 v2.3 백포트)에서 S1 → S2 강등. 최희경(2016) 코퍼스 검증에서 비번역 한국어(84.4)가 번역문(42.1)보다 2배 이상 자주 쓰는 것으로 나와 대표 번역투 통념이 기각됨. 개별 출현은 AI 표지가 아니고 반복만 문체 문제. `see: empirical-validation.md#기각`
- class: ANCHORED
- 표층형: `를 통하여|을 통하여|를 통해|을 통해|를 통한|을 통한`
- 주의(Keep): 1~2회 출현은 keep(evidence: 출현 횟수). 문단 3회+ 반복일 때만 flag.

### A-3. "~에 있어(서)" [S1]
- 패턴: 전제·상황 도입 (영어 `in terms of / when it comes to`)
- 예: "이 문제**에 있어서** 중요한 것은" → "이 문제에서 중요한 것은" / "이 문제를 볼 때"

### A-4. "~라는 점에서" [S2]
- 패턴: 근거 제시 (영어 `in the sense that`)
- 예: "확장성이 뛰어나**다는 점에서** 의미가 있다" → "확장성이 뛰어나서 의미가 있다"
- 주의: 때로는 자연스러움. 한 문서에 3회+ 반복될 때만 제거.

### A-5. "~와 관련하여" / "~와 관련된" [S2]
- 패턴: 주제 지시 (영어 `regarding / related to`)
- 예: "보안**과 관련하여** 주의해야 한다" → "보안에 주의해야 한다"

### A-6. "~에 기반하여" / "~을 바탕으로" 남발 [S2]
- 패턴: 근거 (영어 `based on`)
- 예: "데이터**에 기반하여** 판단한다" → "데이터로 판단한다" / "데이터를 보고 판단한다"

### A-7. "가지고 있다" [S1]
- 패턴: 소유·특성 서술 (영어 `have/possess`)
- 예: "강한 경쟁력을 **가지고 있다**" → "경쟁력이 강하다"
- 처방: 형용사형으로 돌려 서술어 없애거나 "있다"로 단순화.
- class: ANCHORED
- 표층형: `가지고 있다|가지고 있는|갖고 있다|갖고 있는`

### A-8. 이중 피동 "~되어진다" / "~지게 된다" [S1]
- 예: "판단**되어진다**" → "판단된다" / "판단한다"
- 처방: 가능하면 능동으로. 못 바꾸면 단일 피동.
- class: ANCHORED
- 표층형: `되어진다|되어졌다|되어지는|지게 된다|지게 됐다`

### A-9. "~에 의해" 피동문 [S2]
- 패턴: by-passive (영어 수동태 직역)
- 예: "AI**에 의해** 생성된 이미지" → "AI가 만든 이미지"
- 처방: 행위자를 주어로 복귀.

### A-10. "~할 수 있다" 남발 [S2]
- 패턴: 가능형 서술 (영어 `can/be able to`)
- 예: "효율을 높**일 수 있다**. 비용을 줄**일 수 있다**. 시간을 단축**할 수 있다**."
- 처방: 확정 서술 ("높인다", "줄인다")로 톤 전환. 꼭 가능성을 말할 때만 남김.

### A-11. "~을 위해" 목적절 남발 [S2]
- 패턴: `X을 위해 Y한다` (영어 `in order to`)
- 예: "고객 만족**을 위해** 노력한다" → "고객이 만족하도록 일한다"

### A-12. "만들어지다" / "이루어지다" [S2]
- 패턴: 자동화된 피동
- 예: "합의가 **이루어졌다**" → "합의했다" / "합의에 이르렀다"

### A-13. 명사 나열 (조사 생략) [S2]
- 패턴: 영어식 명사구를 조사 없이 붙임
- 예: "AI 기술 발전 속도 가속화" → "AI 기술의 발전 속도가 빨라지고 있다"
- 처방: 적절한 조사("의", "가", "를") 복원.

### A-14. 접속부사 "그리고" 절 연결 [S2]
- 패턴: 영어 `and`처럼 "그리고"로 평문 연결
- 예: "그는 보고했다. **그리고** 자리에 앉았다." → "그는 보고하고 자리에 앉았다."
- 처방: "-고", "-며", "-면서" 등 연결어미로 압축.

### A-15. 추상 주어 + 만능 동사 [S2] · v1.1 신규
- 패턴: 영어 `The X shows / provides / brings Y` 직역. 주어가 사건·현상이고 술어가 "보여준다·제공한다·가져온다·시사한다"
- 예: "DeepSeek-V4**의 등장은** ~을 **보여줍니다**" / "이 전략**은** 지형**을 흔들고 있습니다**" / "X**는** Y**를 제공합니다**"
- 처방: 주어를 행위자(사람·팀·회사)로 돌리거나, 주어·동사 자체를 없애고 직접 서술. "DeepSeek는 ~ 원칙을 이렇게 증명했다" 식.

### A-16. 영어 대명사 직역 (그/그녀/그것/그들) [S1] · v3.0 상류 이식
- 패턴: 영어 `he/she/it/they → 그/그녀/그것/그들` 1대1 매핑. 한국어는 영형(zero) 대명사 생략·명사구 재사용·호칭으로 응결성을 확보. NMT/LLM 출력의 대명사 밀도가 비번역 한국어의 2~3배.
- 예: "존은 피곤했다. **그는** 앉았다. **그는** 한숨을 쉬었다." → "존은 피곤했다. 자리에 앉아 한숨을 쉬었다." / "**그의** 손" → "손"
- 처방: (a) 대명사 출현의 50~70%는 삭제 후보로 문장 재구성, (b) 화자·장면 전환 시점에만 명사구·호칭 명시, (c) 'they'는 "그들"이 아니라 "사람들·우리·일부"로 다양화.
- **적용 범위 (중요)**: **영어 원문을 번역·요약하는 맥락 전용.** 자생 한국어 산문에는 발동 금지 — 대조 실측에서 자생 한국어는 인간이 오히려 `그는/그의`를 더 씀(AI 0.0 vs 인간 1.9/1000어절). 번역 맥락 밖 적용은 사람 글 훼손. `see: empirical-validation.md#재판단`
- class: HOLISTIC
- 출처: 김도훈 2009; Cho et al. 2019 (arXiv:1905.11684)

### A-17. (보류 — hold) 무정물·추상명사 '-들' 기계적 부착
> **Hold 사유**: 상류 v2.0 검증 회차에서 양성 0건. 학술 근거(전영철 2007 등)는 강하나 코퍼스 결정타 부재. ID는 부활 대비 비워둠(patternID 안정성). `metrics_v2.deul_overuse_rate`로 정량 관찰만 지속.

### A-18. 관계대명사절 직역 — 긴 좌향 수식 (관형구 3중+ 중첩) [S2] · v3.0 상류 이식
- 패턴: 영어 관계절(후치)을 한국어 관형절(전치)로 1대1 매핑해 핵 명사 도달 전 작업기억 부담 폭증. NMT/LLM은 영어 SVO를 유지하려 해 좌향 수식이 누적됨(박옥수 2018).
- 예: "그는 **사고를 일으킨 화학물질을 생산한 회사에서 한때 일했던 한 남자를** 만났다." → "그는 한 남자를 만났는데, 그 남자는 사고를 일으킨 화학물질을 만든 회사에서 일했던 사람이었다."
- 처방: 관형절 3어절+ 는 문장 분리 또는 후치 동격절("~를 만났는데, 그 X는 ~")로. 관형구 3중+ 중첩 문장은 무조건 재구성.
- class: COMPUTED
- 지표: relative_clause_nesting >= 2
- 출처: 박옥수 2018; 김채은 2021

### A-19. 이중 조사 결합 (-에서의·-으로의·-에의·-으로부터의) [S2] · v3.0 상류 이식
- 패턴: 일본어 'の'+영어 전치사구 영향의 격조사 이중 결합. 본래 한국어는 절·구로 풀어 씀. **단순 '~의'는 명시 제외**(학계 합의 없음, 15세기부터 존재).
- 예: "긴장**으로부터의** 해방" → "긴장에서 벗어남" / "설문지**에의** 응답" → "설문 답변" / "2층**에서의** 살림" → "2층에서 시작한 살림"
- 처방: 이중 결합만 일괄 점검. 전치사구를 1대1 매핑하지 말고 문장 단위 재해석. 연속 "의 의 의"는 절·구로 풀기.
- class: ANCHORED
- 표층형: `에서의|에로의|으로의|에의|으로부터의|로부터의`
- 출처: 김정우 2007; 김순영 2012

### A-20. '의' 연쇄·과밀 [S3] · fluent-korean 이식 (가독성 관점)
- 패턴: 관형격 조사 '의'를 필요 이상으로 반복. "A의 B의 C의 D" 식 3연쇄+, 또는 문장·문단 단위 '의' 밀도 과다. 영어 of·일본어 の의 1대1 이식에서 자주 발생.
- 예: "사용자**의** 요청**의** 처리**의** 결과" → "사용자 요청을 처리한 결과" / "분석**의** 흐름" → "분석 흐름" / "작업**의** 상황" → "작업이 진행되는 상황"
- 처방: (a) '의' 연쇄는 절·구로 풀거나 복합명사로 압축, (b) 무의미한 '의'는 삭제(명사 직접 결합), (c) '의'를 지우면서 생략됐던 서술 성분을 복원.
- **경계 (중요)**: **단일 '의' 자체는 AI 티가 아니다**(A-19 참조 — 15세기부터 존재, 최소 결합은 자연스러움). 이 규칙은 오직 **연쇄·과밀**만 대상으로 하며, 개별 '의'를 기계적으로 제거하면 오히려 명사 나열(A-13)을 유발한다. S3 — 다른 패턴과 중첩될 때만 손봄.
- class: HOLISTIC
- 출처: snflkd/fluent-korean (output-style 문장단위-1·구단위, MIT)

## B. 영어 인용·용어 과다 — S2

### B-1. 괄호 병기 관습 [S2]
- 패턴: 처음 등장할 때 모든 전문용어에 영어 병기
- 예: "인공지능**(AI)**은 거대언어모델**(LLM)**과 다르다."
- 처방: 해당 문서가 전문 독자 대상이면 1회만 병기, 이후 한국어만. 일반 독자 대상이면 영어 병기 자체를 최소화.

### B-2. 불필요한 영어 장식·일회성 jargon [S2] · v3.0 상류 재정의 이식
> **용어 보존 원칙**: B 카테고리는 "영어가 보이면 지운다"가 아니다. **개발·AI 문맥의 글**에서 이미 굳은 표준 technical term은 의미 보존 대상이다(`API`·`SDK`·`CLI`·`prompt`·`token`·`embedding`·`agent`·`plugin`·`pipeline`·`framework` 등). `prompt`를 "지시문", `agent`를 "대리인"처럼 **기계적으로 직역하지 않는다**.
> - 단, 보존은 독자층·문맥 의존. 일반 독자 대상 글에서는 `span`→"구간", `metric`→"지표"처럼 한국어가 오히려 맞다. 판단 기준: "이 글의 독자가 그 원어를 번역보다 자연스럽게 읽는가."
> - B가 실제로 다루는 것: 설명 없이 낀 광고성 buzzword·반복 괄호 병기·독자층과 안 맞는 과시적 영어.
- 패턴: 한국어 문장에 설명 없이 낀 buzzword가 리듬을 깨거나, 과시적 영어가 반복됨.
- 예: "사용자에게 **seamless**하고 **robust**한 경험을 제공한다" → "사용자가 끊김 없이 안정적으로 쓸 수 있게 한다"
- 처방: (a) 표준 technical term 보존, (b) 광고성 buzzword(seamless·robust·leverage)만 한국어로 풀기, (c) 첫 등장 설명 뒤 한 표기로 통일.
- class: ANCHORED
- 표층형: `(?i)\b(seamless|robust|leverage|synergy|holistic|game.?changer)`
- 주의(Keep): 표준 technical term·고유명사는 keep. buzzword만 flag.

### B-3. 과도한 영어 인용구 [S2]
- 패턴: 영어 문장을 인용문으로 그대로 박아넣고 번역도 병기
- 처방: 정말 원문 어감이 필요한 경우가 아니면 한국어로 풀어쓰고 출처만 병기.

### B-4. "~라고 알려진", "~로 일컬어지는" [S3]
- 패턴: 영어 `known as / so-called` 직역
- 예: "**'AGI'라고 알려진** 범용 인공지능" → "범용 인공지능(AGI)"

## C. 구조적 AI 패턴 (서식·레이아웃) — S1~S2

### C-1. 기계적 병렬 열거 [S2]
- 패턴: "첫째, ~. 둘째, ~. 셋째, ~."가 문단 전체를 지배.
- 처방: **기본은 보존.** 열거는 한국어에서 자연스러운 수사이기도 하다 — 무조건 푸는 것은 글 훼손. 한 문단 4개+ 나열이 메트로놈처럼 읽힐 때만 1~2개를 서술문으로 녹이거나 "우선 / 다음으로 / 마지막으로"로 변주.
- 심각도 이력: v3.0(상류 v2.0.1 백포트)에서 S1 → S2 강등. S1("무조건 제거")과 결합 시 3항 열거까지 전량 해체되는 과잉 윤문 발생(상류 웹앱 실사용 불만 사례).

### C-2. 과도한 불릿 리스트 [S2]
- 패턴: 에세이·칼럼·리포트에서 3개 이상 연속 불릿 블록.
- 처방: 불릿을 산문으로 "녹이기". 정말 나열이 의미 있는 지점만 남김.

### C-3. 반복적 섹션 헤딩 [S2]
- 패턴: `## 도입 ## 본론 ## 결론` 같은 도식적 분절.
- 처방: 산문형 글이면 헤딩 자체를 제거. 리포트형이면 헤딩 문구를 구체화("AI 규제의 세 가지 균열점").

### C-4. 문단 첫 문장 요약 공식 [S2]
- 패턴: 매 문단 첫 문장이 그 문단의 요약(topic sentence). 영어 작문 교본식.
- 처방: 일부 문단은 사례·장면·인용으로 시작하도록 순서를 흐트러뜨림.

### C-5. 이모지 남발 [S1]
- 패턴: `✅ 🚀 💡 ⚠️ 📊` 같은 이모지가 리스트 머리·헤딩·강조에 박혀 있음.
- 처방: 에세이/리포트 문맥이면 전량 제거. SNS·제품 카피가 아닌 이상 AI 티가 극단적으로 강함.

### C-6. 헤딩 아래 한 줄 요약 박스 [S2]
- 패턴: 모든 섹션 헤딩 직후 "이 섹션에서는 ~를 다룬다" 같은 안내문.
- 처방: 삭제. 본문이 바로 들어가야 한국어 글답다.

### C-7. 문단 간 기계적 "먼저·반면·결국" 3단 공식 [S2] · v1.1 신규
- 패턴: 문단 문두가 순서대로 "먼저 ~ / 반면 ~ / 결국 ~" 또는 "첫째 ~ / 둘째 ~ / 마지막으로 ~"로 고정. 한국 필자도 가끔 쓰나, 3연속 이상이면 AI 특유.
- 예: 본 문서 v1 초안 (문단 2 "먼저", 문단 3 "반면", 문단 6 "결국")
- 처방: 3개 중 2개 삭제. 순서 의미는 문단 자체 흐름으로 전달. 문두 접속사 없는 문단도 섞음.

### C-8. 대칭 대구 공식 "A인가, B인가" 반복 [S1] · v1.1 신규 · v3.0 실측 최강 신호
- 패턴: 동일 문서에서 이항 대립이 3회 이상 평행구로 반복. 영어 수사학 직역.
- **실측 판별력 (상류 v2.3 대조 코퍼스)**: 부정 대구 `A가 아니라 B` 밀도 AI 5.8 vs 인간 0.6(**9.2배**, G²=41.7 p<0.0001), 개인 블로그 대비 18배. 세 모델(Fable·GPT·Haiku) 공통 = 모델 계열 무관 "AI다움". A~J 전체 최강 실측 신호. `see: empirical-validation.md#확증`
- 예: "독점**인가**, 확산**인가**" / "전략가에게는 ~, 입안자에게는 ~"
- **부정-긍정 대구 변종(A가 아니라 B)**: "단순히 A가 아니라 B다" / "A라기보다 B다" / "쓰느냐가 아니라 지키느냐다" 식 부정-긍정 평행구 연쇄. 모던 LLM 산문(특히 GPT 계열)의 강한 시그니처 — 문단 전체가 이 틀로만 굴러가는 균일성이 결정타.
- 처방: 연쇄 중 **1개만 살리고** 나머지는 직접 단언으로("A가 아니라 B" → "B가 핵심이다"). 대칭형은 3개 중 2개를 비대칭 재배치.
- class: ANCHORED
- 표층형: `(?:가|이) 아니라|라기보다|이기 이전에|인가,`
- 주의(Keep): **전멸 금지** — 원문 대구 5개+를 전부 죽이면 verify_gates P2 FAIL. 연쇄당 1개는 keep(evidence: 보존 선택).

### C-9. 숫자 괄호 인덱싱 "1) 2) 3)" [S2] · v3.0 상류 이식
- 패턴: 동일 문단·인접 문장에서 `1) ... 2) ... 3) ...` 나열. C-1(첫째·둘째)·C-2(불릿)와 별개 표기 시그니처. LLM은 항목 3개면 거의 자동으로 이 형식을 씀.
- 처방: 3개 중 1개는 서술문으로 녹이고 나머지는 "우선~", "다음으로~"로 변주. 진짜 나열이 의미 있을 때만 유지하되 문서 1회 이하.
- class: ANCHORED
- 표층형: `(?m)(?:^|\s)[1-3]\)\s`
- 주의(Keep): 법령·계약 인용의 원문 번호 체계는 keep.

### C-10. 콜론 부제 헤딩 공식 "X: Y" [S2] · v3.0 상류 이식
- 패턴: 헤딩에 자동으로 "메인 라벨: 부제"를 박는 공식. C-3(도식 분절)과 별개 — 헤딩 자체의 콜론+부제 구조.
- 예: "### 서론: 제조업의 미래, AI에 달려있다" / "## 핀테크, '일상'을 넘어 '생태계'로"
- 처방: 콜론+부제를 제거하고 단일 명사구·동사구로 압축. 부제가 필요하면 본문 첫 문장에 녹이기. 문서 1회 이하.
- **예외**: 학술·보고서의 실제 절 제목(번호 절·장 제목)은 보존 — 제거·개작·본문 흡수 금지.
- class: ANCHORED
- 표층형: `(?m)^#{1,4}\s+[^:\n]{2,30}:\s+\S`
- 주의(Keep): 학술·보고서 절 제목은 keep(evidence: 장르).

### C-11. 연결어미 뒤 쉼표 [S1] · v3.0 상류 이식 (KatFish 4.84배)
- 패턴: 연결어미(-고/-며/-지만/-면서/-아서·어서/-는데) 직후 쉼표. 인간은 연결어미 자체가 호흡 단위라 추가 쉼표가 불필요한데 AI는 영어 comma-after-conjunction 감각을 이식. **단일 지표 최강 분리도**(KatFish 에세이 인간 4.10% vs AI 19.83%).
- 예: "발전하**지만,** 대응은 더디다" / "정제하**고,** 학습시킨다"
- 처방: 연결어미 뒤 쉼표 일괄 제거. 호흡이 길면 마침표 분할 또는 주절 경계로 쉼표 이동. 6회+ = S1, 3~5회 = S2.
- class: ANCHORED
- 표층형: `[가-힣](?:고|며|지만|면서|는데|아서|어서),`
- 주의(Keep): 뒤에 삽입절·인용이 이어져 쉼표가 문법적으로 필요한 경우 keep.

### C-12. 쉼표 포함률 (문서 단위) [S2] · v3.0 상류 이식
- 패턴: 쉼표 1개+ 포함 문장 비율이 50% 초과. C-11(위치 특이)과 측정 차원이 다름 — 문서 전체 분포(KatFish 인간 26.31% vs AI 61.03%).
- 처방: 초과 시 일부 문장을 (a) 마침표 분할 단문화, (b) 연결어미 흡수, (c) 쉼표 삭제.
- class: COMPUTED
- 지표: comma_inclusion_rate > 0.5 and sentence_count >= 5

## D. AI 특유의 관용구 (Signature Phrases) — S1

한국어 인간 필자가 거의 쓰지 않지만 LLM이 반복적으로 산출하는 상투구. 발견 즉시 교체.

**역방향 삽입 금지** (v3.0 상류 이식): 이 카테고리의 어휘는 **제거 대상이지 생성 대상이 아니다.** 윤문 과정에서 원문에 없던 D 계열 상투구("괄목할 만한"·"~로 평가된다"·"주목받았다"·"의미가 크다" 류)를 새로 삽입하는 것은 자기모순이며 금지. 원문의 살아있는 표현을 상투구로 갈아끼우는 것은 윤문이 아니라 역주행이다.

### D-1. 종결·요약류
- "결론적으로", "요약하면", "종합하면", "정리하자면"
- "~라고 할 수 있다" / "~라고 볼 수 있다"
- "~라 하겠다", "~라 할 것이다"
- "~에 다름 아니다"
- class: ANCHORED
- 표층형: `결론적으로|요약하면|종합하면|정리하자면|라고 할 수 있다|라고 볼 수 있다|에 다름 아니다`

### D-2. 의의·중요성 과장
- "매우 중요하다", "반드시 기억해야 한다"
- "시사하는 바가 크다", "주목할 만하다"
- "간과할 수 없다", "무시할 수 없다"
- "~의 지평을 연다", "~에 방점을 찍는다"
- "그 의미가 적지 않다", "의미심장하다"

### D-3. 열거 도입
- "크게 세 가지로 나눌 수 있다"
- "다음과 같은 특징을 가진다"
- "다음과 같이 요약할 수 있다"

### D-4. AI 티 특화
- "혁신적인", "획기적인", "전례 없는" (hype 어휘)
- "~의 가능성을 열어준다"
- "~의 새로운 장을 열다"
- "~시대가 도래했다"

### D-5. 의인화된 추상 주어 [S2] · v1.1 신규
- 패턴: 사건·기술·개념을 주어로 삼아 인간 행위처럼 서술. AI가 글을 "무게감 있게" 보이게 하려는 기본 동작.
- 예: "**두 지능의 충돌**이 질문을 **던집니다**" / "**AI 대전**이 **끝나지 않습니다**" / "**지능의 가성비**가 **증명합니다**"
- 처방: 실제 행위자로 주어 교체("두 회사의 경쟁은", "엔지니어들은"), 또는 의인화 동사 약화("던집니다"→"남습니다"·"생깁니다"). 단, 상징적 제목·요약 1회 정도는 허용.

### D-6. 완결 공식형 결말 "~할 때입니다 / 시점입니다" [S2] · v1.1 신규
- 패턴: 칼럼·리포트 마지막 문장이 "~해야 할 때입니다", "~로 나아갈 시점입니다", "~할 순간입니다" 공식.
- 예: "에이전트 정부의 시대로 **나아가야 할 때입니다**"
- 처방: 동일 의미를 구체 동사 단언으로. "에이전트 정부 단계로 **넘어갈 때입니다**" 정도까지는 허용(덜 과장). 한 문서에 한 번만.

### D-7. 변환 공식 "X에서 Y로 / X을 넘어 Y로" [S2] · v3.0 상류 이식
- 패턴: 패러다임 전환·진화를 표현할 때 거의 자동 사용. D-1·D-6과 별개의 결산/슬로건 공식 — **변환의 방향성** 강조. Gemini-우세 시그니처.
- 예: "**'규모의 경쟁'에서 '전략의 경쟁'으로**" / "**'데이터 조회'를 넘어 '맞춤형 금융 비서'로**"
- 처방: 직접 단언으로("'지식 전달자'에서 '학습 조력자'로" → "교사는 더 이상 지식 전달자가 아니다. 학생 곁에서 학습을 돕는다"). 문서 1회 이하.
- class: ANCHORED
- 표층형: `(?:을|를) 넘어 |['"'"].{1,20}['"'"]에서 ['"'"].{1,20}['"'"](?:으로|로)`
- 주의(Keep): 물리적 이동·경계 통과("고개를 넘어")는 keep.

**처방:** 대부분 **삭제**. 의미가 필요하면 구체 명사·동사로 치환("중요하다"→"핵심이다" 혹은 구체 근거로).

## E. 리듬·문장 길이 균일성 — S2

### E-1. 문장 길이 표준편차 낮음 — 특히 장문 부재 · v3.0 실측 재정의
- 모든 문장이 30~50자 부근에 몰려 있음. **실체는 "균일"보다 "장문 부재"**: 대조 실측에서 100자+ 문장이 AI 8.1 vs 인간 91.3(1000문장당, 11배). AI는 짧은 문장만 찍고 긴 호흡을 못 만든다.
- 처방: 단문(10~15자) 1~2개 + **장문(80~100자+) 1개**를 문단마다 혼용. 단, 인접 문장을 이어 붙일 때 **원문에 없는 내용 추가 금지**(잇기만).
- class: COMPUTED
- 지표: sentence_len_stdev < 8 and sentence_count >= 5

### E-2. 동일 종결어미 반복
- "~이다. ~이다. ~이다."
- "~한다. ~한다. ~한다."
- 처방: "~다"·"~았다"·"~인 것"·명사형 종결을 섞음. 인간 필자는 무의식적으로 변주함.
- **명사형 종결 구분 (조건부) · fluent-korean 이식**: 여기서 권장하는 명사형 종결은 **리듬 변주용 소량 삽입**(단조로운 "~다" 반복을 깨는 용도)이다. 반대로 서술어·종결어미를 계통적으로 생략해 문장 대부분을 명사구로 끝맺는 **전보식(telegraphic) 명사 종결**은 기계-한국어 신호이므로 제거 대상 — 이 경우 A-13(명사 나열)·I-1(것이다 종결)로 처리하고 서술어·종결어미를 복원한다. 요약: 명사형 종결은 "가끔 = 변주(유지), 지배적 = 기계체(제거)". `see: fluent-korean output-style 문장단위-2`

### E-3. 모든 문단 3~4문장 공식
- 문단 길이도 균일.
- 처방: 1문장 문단 / 6문장 문단을 의도적으로 섞음.

### E-4. 단문 일변도 (복문·중문 부재) [S2] · v3.0 상류 이식
- 패턴: 문장 대부분이 단문으로만 끊기고 연결어미·관형절·인용절 복문이 거의 없음. E-1과 짝패턴 — E-1은 길이, E-4는 **구조의 단조성**.
- 예: "AI는 빠르게 발전한다. 기업은 따라가야 한다. 시간이 없다. 데이터가 핵심이다."
- 처방: 인접 단문 2~3개를 연결어미(-며·-고·-는데)·관형절로 묶어 복문화. 단문 60% 전후, 복문·중문 30%+. 단문은 강조·전환에만.
- class: HOLISTIC

### E-5. 쉼표 분절 평균 길이 (긴 절 구조) [S2] · v3.0 상류 이식
- 패턴: 쉼표로 분절된 절의 평균 어절 수가 김 — 영어식 long-sentence 구조(KatFish 인간 4.35어절 vs AI 8.56어절). E-4와 반대 극단, 둘 다 AI 시그니처.
- 처방: 8어절+ 절은 마침표 분할 또는 한국어 관형절로 압축. E-4와 동시 위반 시 가중.
- class: COMPUTED
- 지표: comma_segment_length > 7 and sentence_count >= 5

### E-6. 쉼표 전후 품사 다양성 높음 [S2] · v3.0 상류 이식 · 장르 가드
- 패턴: 쉼표를 다양한 품사 경계에 무차별 삽입(KatFish 인간 24.38 vs AI 59.39). **에세이·뉴스·블로그·보고서 한정** — 시·소설은 분리도 약함.
- 처방: 쉼표를 (a) 주절 경계, (b) 명백한 동격·삽입에만 한정.
- class: HOLISTIC

### E-7. 청자 경어법 일관성 손실 (해라/해요/합쇼체 혼재) [S2] · v3.0 상류 이식 · 장르 가드
- 패턴: 격식 단계(해라·하게·하오·해요·합쇼)가 한 문서·대화 안에서 뒤섞임. E-2(단일 어미 반복)와 축이 다름 — E-7은 **격식 일관성**.
- 예: "도와주시겠습니까?(합쇼)" 직후 "도와줘?(해라)" / 한 문단 "~합니다" 다음 문단 "~한다" 점프.
- 처방: 문서 시작 시 청자 등급을 정하고 일관 유지. **대화·구어 텍스트 한정 적용**(격식체 단일 장르는 미적용).
- class: HOLISTIC
- 출처: 김혜영 2019 (임계 estimated)

## F. 과도한 수식·중복 — S2

### F-1. 정도부사 중독
- "매우", "정말", "진짜로", "대단히", "극히"
- 처방: 대부분 삭제. 강조가 필요하면 구체 수치·사례로 대체.
- class: ANCHORED
- 표층형: `매우|대단히|극히|진짜로`

### F-2. 동의어 이중 수식
- "중요하고 핵심적인 역할"
- "새롭고 혁신적인 접근"
- "지속적이고 꾸준한 노력"
- 처방: 두 수식어 중 하나만 남김.

### F-3. 기능+역할 복합구
- "~로서의 역할과 기능"
- "~의 의미와 가치"
- 처방: 하나만.

### F-4. 과잉 접두·접미
- "~적 측면", "~적 관점"
- "~성(性)", "~화(化)" 남발
- 예: "**근본적 관점**에서 **구조적 변화**가 **필연적**이다" → "구조가 근본부터 바뀐다"

### F-5. "~적 N" 복합 추상어 체인 [S2] · v1.1 신규
- 패턴: 명사 앞 "~적 N" 형태가 한 문서에 3회 이상 반복. F-4와 달리 추상 관형("적 측면/관점")이 아닌 **구체 명사 앞 "~적 N"** 체인. 원문의 지적 권위를 AI가 흉내 낼 때 빈출.
- 예: "에이전트**적** 자율성", "기술**적** 안정성", "경제**적** 자립", "기술**적** 토대", "시스템**적** 접근", "구조**적** 변화"
- 처방: 해당 "~적 N"을 (a) "~로서의 N" ("에이전트로서의 자율성"), (b) 동사구 ("기술이 얼마나 안정적인가"), (c) 구체 명사 ("토대") 중 하나로 해체. 문서 전체에서 "~적 N" 밀도를 절반 이하로.

### F-6. 은유 어휘 오용 (일반어 자리의 비유 표현) [S3] · fluent-korean 이식
- 패턴: 일반 명사·동사로 충분한 자리에 비유적·수사적 어휘를 넣어 의미가 흐려짐. 기술·설명 맥락에서 특히 가독성 저하와 의미 변질을 유발.
- 예: "코드로 **박는** 자리" → "코드에 명시하는 부분" / "요청을 **받습니다**" → "요청을 확인했습니다" / "지형을 **흔든다**" → "시장 구도를 바꾼다"
- 처방: 비유가 (a) 일상 문어에서 통용되고 (b) 해당 분야 관용 표현으로 정착된 경우만 유지. 그 외에는 일반 어휘로 환원. 관용화된 은유를 억지로 풀면 오히려 어색하므로 무차별 적용 금지.
- **경계**: 문학·에세이 장르에서는 비유가 정당한 표현 자원이므로 미적용. 기술 문서·보고서·설명문 한정.
- class: HOLISTIC
- 출처: snflkd/fluent-korean (output-style 구단위-3, MIT)

### F-7. 현학적 고어·희귀어 [S3] · fluent-korean 이식 (자연스러움 관점)
- 패턴: 상용어로 충분한 자리에 예스럽거나 희귀한 한자어·고어를 선택해 문장이 부자연스럽게 현학적으로 읽힘. (fluent-korean은 코딩 에이전트가 brevity 압력 하에 희귀 어휘를 남발하는 현상을 지목.)
- 처방: 대다수 독자가 즉시 이해하는 상용어로 대체. 단, 전문 분야에서 정착된 술어는 유지.
- **주의 (empirical)**: 고전적 ChatGPT AI 티는 오히려 *상투적·일반적* 어휘 쪽이라, 고어·희귀어는 코퍼스로 검증된 AI 시그니처가 아니라 **자연스러움/가독성 예방 규칙**이다. S3 — 강제 제거보다 리뷰어 판단에 위임. ANCHORED 승격 금지(오탐 위험).
- class: HOLISTIC
- 출처: snflkd/fluent-korean (output-style 어휘 지침, MIT)

## G. 과도한 Hedging (완곡) — S2

### G-1. 추측·관측형 종결
- "~할 수 있을 것으로 보인다"
- "~인 것으로 판단된다"
- "~라고 여겨진다"
- "~인 듯하다"가 모든 문장 끝에 붙음
- 처방: 단언할 수 있는 곳은 단언. hedging은 정말 불확실한 지점에만.

### G-2. 이중·삼중 완곡
- "~할 가능성이 있을 수 있다"
- "~로 보여질 수 있다"
- 처방: 하나만 남김.

### G-3. 안전 균형 lexicon (Safe Balance Score) [S2] · v3.0 상류 이식
- 패턴: "양쪽 모두 / 두 가지 모두 / 장점도 있지만 / 신중하게 / 균형" 등 균형·양면성 어휘 빈도 과다(KatFish lexicon 지표). G-1(종결어미 단위)과 달리 **lexicon 단위** — 위험 회피·양면 제시 성향.
- 예: "**양쪽 모두** 일리가 있다 / **장점도 있지만** 단점도 있다 / **신중하게** 접근해야 한다 / **균형** 잡힌 시각"
- 처방: (a) 한쪽 단언, (b) 구체 사례 비교, (c) 조건부("X일 때는 A, Y일 때는 B")로 변환. 문서 4회+ 시 S2.
- class: ANCHORED
- 표층형: `양쪽 모두|두 가지 모두|장점도 있지만|신중하게|균형 잡힌|균형을`
- 주의(Keep): 1~3회 출현·실제 재무/물리적 균형 언급은 keep.

## H. 접속사 남발 — S2

### H-1. 문두 접속사 과다
- 매 문장·매 문단 시작에 "또한", "따라서", "즉", "나아가", "아울러", "게다가", "더욱이"
- 처방: 70% 이상 제거. 논리 흐름은 문장 내용 자체로 드러나야 함. 정말 역접·인과 강조가 필요할 때만.

### H-2. "하지만"과 "그러나" 혼용 남발
- 역접이 문단마다 등장.
- 처방: 반절 이상 삭제. 대비가 자명하면 접속사 없이도 통함.

### H-3. "이는 ~" 지시 반복
- "이는 ~을 의미한다"
- 처방: 앞 문장과 붙이거나 구체 서술로 치환.

### H-4. 재정의 접속사 "즉" 남발 [S2] · v1.1 신규
- 패턴: 영어 `i.e.` / `that is` 직역. 보충 설명이 필요할 때마다 "즉"을 앞에 붙임.
- 예: "AI 민주화, **즉** 경제성 측면에서"
- 처방: "곧", "말하자면", "다시 말해", "바꿔 말하면"으로 어휘 변주. 또는 아예 생략하고 앞뒤를 쉼표로만 연결. 한 문서에 "즉" 2회 이하로 제한.
- class: ANCHORED
- 표층형: `즉[\s,]`

## I. 형식명사·의존명사 과다 — S2

### I-1. "것이다" 종결 남발 · v3.0 실측 재조정
- "~한 것이다", "~일 것이다"가 문단의 대표 종결.
- 처방: **연속 3회+ 남발일 때만** 일부를 확정 서술 "~다"로. **기본은 보존.**
- 근거: 대조 실측에서 `~것이다` 종결은 AI 20.4 vs 인간 43.0(1000문장당, **인간이 2배**). 한국어 논설문의 일반 종결이지 AI 티가 아니다. 반복 편중만 문체 문제. `see: empirical-validation.md#기각`
- class: ANCHORED
- 표층형: `것이다|것입니다`
- 주의(Keep): 연속 3회 미만은 keep(evidence: 연속 횟수). 무조건 평탄화 금지.

### I-2. "점", "바", "수", "데" 반복
- "주목할 **점**은", "나아갈 **바**는", "할 **수**가 있다", "하는 **데**에"
- 처방: 구체 명사·동사로 치환 또는 삭제.

### I-3. "~라는 것"
- "변화가 크**다는 것이다**."
- 처방: "변화가 크다." (종결어미 직결)

### I-4. "~할 필요가 있다"
- 영어 `should/need to` 직역.
- 처방: "~해야 한다" 혹은 구체 권고형.

### I-5. "~이/가 필요하다"
- "혁신이 필요하다", "변화가 필요하다"
- 처방: 누가 무엇을 해야 하는지 주어·동사로 구체화.

### I-6. "~능력" 추상명사 연쇄 [S2] · v1.1 신규
- 패턴: "N 능력"이 한 문서에 3회 이상 반복되며 동사 대신 명사구로 능력을 서술. 영어 `ability to X / X capability` 직역 감성.
- 예: "사고 **능력**", "워크플로우 수행 **능력**", "장기 문맥 유지 **능력**", "추론 **능력**"
- 처방: 동사형으로 풀기. "사고 능력은 뛰어나다" → "잘 사고한다" / "사고의 수준이 높다". "워크플로우 수행 능력" → "워크플로우를 얼마나 잘 처리하는지". 한 문서에 "~능력" 2회 이하로 제한.

## J. 시각 장식 남용 — S2~S3

### J-1. 과도한 **볼드**
- 문장마다 핵심 단어 볼드.
- 처방: 본문에서 볼드는 거의 제거. 시각적 소음만 발생.

### J-2. 따옴표 과다
- 개념어·강조어에 "" 남발.
- 처방: 진짜 인용·특수 용례에만 한정.

### J-3. 대시(—) 남용 · benelog 줄표 규칙 흡수(v3.1)
- 패턴: 영어 em-dash 스타일로 부가 설명·문장 연결·용어 해설·제목 부제를 대시로 처리. 본문 문장 안에서 대시를 쓰지 않는다.
- 예: "AI는 도구 — 그 이상도 이하도 아닌 — 이다"
- **치환 레시피 (용법별)**:
  - 삽입구 → **괄호**: "관계형 스키마 — 외래 키, JOIN — 를" → "관계형 스키마(외래 키, JOIN)를"
  - 문장 연결 → **문장 분리**: "~와 비슷하다 — 지역 변수가 ~" → "~와 비슷하다. 지역 변수가 ~"
  - 용어 해설 → **서술문화** 또는 대시 제거 후 재구성: "**용어** — 설명이다" → "**용어**는 설명이다"
  - 제목·목차의 "제목 — 부제" → **부제를 본문 첫 문장으로 내리거나 제목 단일화**
- **콜론 치환 금지 (확정 방침)**: benelog 원안은 대시를 콜론(`제목: 부제`, `용어: 설명`)으로 바꾸지만 **이 플러그인은 채택하지 않는다.** 콜론(부제·해설)은 요청이 없는 한 제거가 원칙이며 `C-10`(콜론 부제 헤딩)·`C-3`와 정합해야 한다. 대시는 항상 **괄호·문장 분리·서술문**으로 해소한다.
- 밀도 목표: 본문 대시 1문서 1~2회 이하.
- class: ANCHORED
- 표층형: `[—–]`
- 주의(Keep): **코드 블록·인라인 코드·설정 파일이나 실제 출력을 인용한 문자열**(예: `PASS — ...`) 안의 대시는 원문 보존 = keep(evidence: 코드/인용). 조판용 범위 대시(`2020–2024`)도 keep.

### J-4. 괄호 부연 과다
- "(이는 ~을 의미한다)" 같은 부연이 반복.
- 처방: 괄호 부연 대부분 본문화 또는 삭제.

## L. 추상 은유 어휘 (Abstract Metaphor Lexicon) — S2

구체 명사/동사가 들어갈 자리를 어떤 맥락에도 문법적으로 들어맞는 범용 은유로 덮은 흔적. 독자가 사라진 정보를 복원하려고 되묻게 만든다. 원 출처: `benelog` "클로드 문체 없애기 지침". 전부 ANCHORED이며, 각 규칙의 **주의(Keep)** 조항은 정당한 물리적·관용적 용법을 보존한다. detector는 후보를 받아 Keep 조건에 맞으면 keep(+증거 토큰), 아니면 flag한다.

### L-1. "무너진다" 추상 남용 [S2]
- 패턴: 실제 붕괴가 아닌데 실패·와해를 "무너진다"로 은유.
- 예: "이 가정이 **무너진다**" → "이 가정이 성립하지 않는다"
- 처방: 무엇이 어떻게 잘못되는지 구체 서술. 보안 문맥이면 실제 사건 동사("뚫린다").
- class: ANCHORED
- 표층형: `무너진다|무너졌다|무너지는|무너질|무너져`
- 주의(Keep): 물리적 붕괴 + 즉각적 결과를 서술할 때는 허용.

### L-2. "맞물린다" 추상 남용 [S2]
- 패턴: 관계를 "맞물린다"로 뭉뚱그림.
- 예: "두 정책이 **맞물려** 있다" → "두 정책이 서로를 전제한다 / A가 B의 조건이다"
- 처방: 인과·근거·결합·사용·호환 중 실제 관계를 명시.
- class: ANCHORED
- 표층형: `맞물린다|맞물려|맞물리는|맞물린|맞물릴`
- 주의(Keep): 문자 그대로 기계적으로 맞물리는 경우는 허용.

### L-3. "가른다/갈린다" 추상 남용 [S2]
- 패턴: 구분·결정을 "가른다/갈린다"로 은유.
- 예: "성능이 승패를 **가른다**" → "성능이 승패를 정한다 / 승패는 성능에 달렸다"
- 처방: "나뉜다", "구분한다", "정한다", "~에 달렸다"로 정밀화.
- class: ANCHORED
- 표층형: `가른다|가르는|가를|갈린다|갈리는|갈릴|갈렸다|갈라`
- 주의(Keep): 물리적 분할, 관용구 "의견이 갈린다", 맥락이 확립된 분기 은유는 허용.

### L-4. "무겁다/가볍다" 추상 남용 [S2]
- 패턴: 다축(메모리·지연·학습량·크기)을 1차원 형용사로 사영.
- 예: "이 모델은 **무겁다**" → "이 모델은 추론 지연이 크다 / 메모리를 40GB 쓴다"
- 처방: 실제 기준(메모리·크기·시간·절차)을 명시.
- class: ANCHORED
- 표층형: `무겁다|무거운|무거워|가볍다|가벼운|가벼워`
- 주의(Keep): 물리적 무게, 관용구 "말의 무게"는 허용.

### L-5. "지점" 추상 남용 [S2]
- 패턴: 부분·대목·곳을 "지점"으로 치환.
- 예: "논의가 갈리는 **지점**" → "논의가 갈리는 대목"
- 처방: "부분", "곳", "대목" 등으로 치환. 기술적 fixture·실제 장소는 유지.
- class: ANCHORED
- 표층형: `지점`
- 주의(Keep): 좌표·측정 지점, 은행 지점 등 실제 장소·기술 용법은 허용.

### L-6. "축" 추상 남용 [S2]
- 패턴: 기준·원인·항목·구성요소를 "축"으로 은유.
- 예: "비용이라는 **축**에서" → "비용이라는 기준에서"
- 처방: "기준", "원인", "항목", "구성 요소"로 치환.
- class: ANCHORED
- 표층형: `(?:^|[\s(])축(?:을|이|은|의|으로|과|도|에서|에)`
- 주의(Keep): 실제 2차원 좌표계·그래프 축은 허용. (복합어 구축·축적 등은 detector가 keep)

### L-7. "겹" 추상 남용 [S2]
- 패턴: 개수·관계를 "겹"으로 은유.
- 예: "여러 **겹**의 의미" → "의미가 세 층으로 나뉜다 / 뜻이 두 가지다"
- 처방: 실제 개수나 구체 관계로.
- class: ANCHORED
- 표층형: `여러 겹|겹겹|겹의|겹을|겹이|겹으로`
- 주의(Keep): 실제 층상·물리적 겹침은 허용.

### L-8. "손잡이" 추상 남용 [S2]
- 패턴: 제어·설정을 "손잡이"로 은유.
- 예: "이 파라미터가 성능의 **손잡이**다" → "이 파라미터로 성능을 조절한다"
- 처방: 무엇을 어떻게 조정하는지 명시.
- class: ANCHORED
- 표층형: `손잡이`
- 주의(Keep): 물리적 손잡이는 허용.

### L-9. "사실상" 남용 [S2]
- 패턴: 불필요한 완충·강조로 "사실상"을 삽입.
- 예: "**사실상** 표준이다" → (정착 용어면 유지) / "표준이다"
- 처방: 정착 용어(de facto)·정밀 한정이 필요할 때만. 아니면 삭제·환언.
- class: ANCHORED
- 표층형: `사실상`
- 주의(Keep): "사실상 표준(de facto)" 등 확립된 용어·필수 한정은 허용.

### L-10. "~인 셈이다" 남용 [S2]
- 패턴: 일반 결론을 "~인 셈이다"로 뭉뚱그림.
- 예: "비용을 절반으로 줄인 **셈이다**" → "비용을 절반으로 줄였다"
- 처방: 은유를 마무리할 때만. 일반 결론은 직접 단언형으로.
- class: ANCHORED
- 표층형: `셈이다|셈입니다|셈이었다|셈이지`
- 주의(Keep): 앞의 은유·비유를 마무리하는 결론일 때는 허용.

### L-11. "결" 추상 남용 [S2] · gist 미수록·동류 확장
- 패턴: 성격·방향·톤·질감을 1음절 은유 "결"로 덮음.
- 예: "논의의 **결**이 다르다" → "논의의 방향이 다르다 / 성격이 다르다"
- 처방: "성격", "방향", "톤", "질감" 중 특정.
- class: ANCHORED
- 표층형: `(?:^|\s)결(?:이|의|을|은|도|[\s.,])`
- 주의(Keep): 나뭇결·물결·살결 등 물리적 결은 허용. (결과·결정·연결 등 복합어는 표층형에서 배제됨)

## 탐지 출력 스키마 (Detector → Rewriter 공유 계약) — v2.0

탐지기는 `02_candidates.json`(prescan 산출)을 입력으로 받아 다음 JSON을 생산한다. **ANCHORED 후보는 반드시 `findings`(flag) 또는 `kept`(보존) 중 하나로 소진해야 하며, `reconcile.py`가 이를 코드로 강제한다.**

```json
{
  "meta": {
    "input_length": 1820,
    "detected_count": 37,
    "ai_tell_density": 0.203,
    "severity_weighted_score": 71.5,
    "taxonomy_version": "2.0",
    "taxonomy_hash": "<candidates.meta.taxonomy_hash를 그대로 echo>",
    "coverage": {
      "L-8": {"candidates": 3, "flagged": 2, "kept": 1},
      "A-2": {"candidates": 6, "flagged": 6, "kept": 0}
    }
  },
  "findings": [
    {
      "id": "f001",
      "candidate_id": "A-2:142",
      "category": "A-2",
      "category_label": "번역투: ~를 통해 남발",
      "severity": "S1",
      "scope": "span",
      "text_span": "데이터 분석을 통해",
      "start": 142,
      "end": 153,
      "reason": "'통해'가 본문에서 6회 반복되어 경로 서술이 기계적",
      "suggested_fix": "데이터를 분석해서"
    }
  ],
  "kept": [
    {
      "candidate_id": "L-8:512",
      "rule_id": "L-8",
      "reason": "물리적 문 손잡이를 가리킴 — 은유 아님",
      "evidence": "문 손잡이"
    }
  ],
  "category_summary": {
    "A": 12, "B": 3, "C": 2, "D": 8, "E": 1,
    "F": 4, "G": 2, "H": 3, "I": 1, "J": 1, "L": 5
  }
}
```

- `severity_weighted_score`: S1=5, S2=2, S3=0.5 가중 합. 0~100 스케일로 정규화.
- `ai_tell_density`: 탐지 span 총 글자 수 / 전체 글자 수.
- **`candidate_id`**: prescan이 부여한 `{rule_id}:{start}`. detector는 offset을 재계산하지 말고 후보의 값을 **echo**한다.
- **`kept[]`**: flag하지 않고 보존한 ANCHORED 후보. `evidence`(검증 가능한 증거 토큰) **필수** — 없으면 reconcile FAIL(mass-keep 억제, H2).
- **`meta.coverage`**: 규칙별 `{candidates, flagged, kept}` = **판정 완결성**. 탐지 recall(표층형이 활용형을 놓쳤는지)은 별도 `tests/gold/`로 측정한다 — coverage 100%가 recall 100%를 뜻하지 않는다.
- **COMPUTED 규칙**: 트리거 시 대응 `findings`(scope=document) 필수. reconcile이 지표를 재계산해 검증.

### reconcile 게이트 계약
`scripts/reconcile.py`가 파이프라인에서 다음을 강제한다(위반 시 종료 코드 1 → 중단):
1. taxonomy 해시 3자 정합(현재 파일 == candidates 스탬프 == detection echo).
2. 모든 ANCHORED 후보 소진(`candidates == flagged + kept`, 미소진 0).
3. 트리거된 COMPUTED 규칙마다 대응 finding 존재.
