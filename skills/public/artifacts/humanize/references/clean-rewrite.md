# Clean-current-state rewrite

Load this reference only when the user explicitly requests a clean-current-state
rewrite of a named artifact or bounded set of artifacts. Ordinary Humanize
requests, the five genre modes, bloat-only editing, and move-only reordering keep
their own selection rules. This is a separate, opt-in operation.

## Establish the bounded inventory

Name the selected artifact, the allowed scope, the fact universe, and the trust
boundary before editing. Read the selected artifact and the relevant nearby
artifacts in that bounded universe. Record load-bearing facts, numbers, names,
identifiers, quotations, requirements, modality, negation, conditions,
exceptions, uncertainty, contracts, links, and the evidence on which a claim
depends.

Find every occurrence without changing it. Use two independently evidenced
searches so the first search is not treated as complete. Classify each occurrence
as exact, paraphrase, partial, stale, or contradictory. Select the canonical home
using authority, maintenance, and proximity to the selected change. Write a
per-occurrence plan that preserves unique detail, contracts, and conflicting
evidence.

If the artifact, fact universe, trust boundary, or allowed scope is materially
ambiguous, ask one focused question about the fork that changes the result and
stop the mutation. If the inventory is incomplete, continue authorized
read-only discovery and do not invent a disposition.

## Rewrite only the selected current state

Remove patch history, duplicated explanation, and discarded-choice residue only
when they are obsolete and inside the selected scope. Preserve the original
intent, load-bearing information, verified content, unique detail, conditions,
uncertainty, and authority. Replace duplicated text with a live reference only
after its canonical home and occurrence plan are recorded. Do not edit immutable
research, historical evidence, unrelated work, concurrent user edits, or any
artifact outside the selected fact universe.

Reuse valid existing authorization when it matches the selected target, action,
and scope. If it does not exist, prepare the concrete proposal before requesting
the required approval. Inventory and approval precede mutation.

## Verify and return

Keep the rewrite as a candidate outside the target and verify the candidate before changing the target. Compare it with the inventory. Check preserved
facts and contracts, live links, lost information, orphan or dangling
references, and residual contradictions. Check nearby artifacts within the
selected fact universe. A review-only request returns findings without
rewriting. If a content check fails or a contradiction remains unresolved, do
not submit the candidate for commit; return the bounded findings or proposal.

Capture the target's source hash and file identity before preparing the
candidate. Commit a verified candidate only through a trusted conditional-write adapter bound to the exact target, source hash and identity, and candidate hash.
If the target has drifted, the adapter reports a conflict, or trusted adapter
evidence is unavailable, do not write, merge, or roll back. Leave the current
target bytes untouched and report the conflict or unavailable boundary. A local
reread followed by a rename or replacement is not evidence of an atomic
conditional write.

Return the requested artifact in the requested format. Keep the inventory,
source comparison, decisions, and progress outside the returned artifact; do not add a progress report or new analysis to the rewrite. Honor a body-only
output request.

Preserve the original provenance, concurrent user edits, and unrelated user
changes. This operation does not authorize a public catalog entry or a remote
effect.
